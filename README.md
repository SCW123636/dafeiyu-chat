# 大肥鱼聊天

一个跑在自己电脑上的 QQ 私聊机器人。目标不是做客服，是让对面的人觉得「在跟一个温柔、有点甜、会记得事的姐姐聊天」。

基于 NapCat + OneBot 11 反向 WebSocket 接 QQ，用 DeepSeek 生成回复，本地 SQLite 存记忆和指标，附一个只绑定 `127.0.0.1` 的中控台。

> 这是个人项目，不是产品。协议层用的是非官方实现，请务必用小号，详见下面的「安全与合规」。

## 它做什么

- **私聊对话**：收消息 → 判断消息形态 → 合并连发 → 生成 1–2 条短气泡 → 逐条发送，每条之间有停顿，发送前显示「正在输入」
- **像真人的表达**：不打句号顿号、经常只有半句、不逐条回应对方说的每件事；按消息类型掷形态（反应 / 半句 / 自己的事 / 吐槽 / 问一句 / 连发 / 表情 / 认真），88% 的情况只发一条
- **长期记忆**：每人的历史、关系摘要、事实库（「你在准备考试」「你搬去上海了」），跨重启保留，支持 `/记忆` `/忘掉` `/清空记忆`
- **关系状态**：在忙什么、没落地的事、沟通偏好、雷区，和事实一起每 6 轮后台整理一次
- **情绪状态**：开心 / 害羞 / 得意 / 委屈 / 生气，2 小时衰减、24 小时复位，会影响语气
- **读图**：对方发表情包只看情绪，不发图片说明；发截图照片时读内容
- **表情包**：按标签从本地表情库挑一张，附在最后一条气泡后（表情库不随本仓库分发，见「素材与授权」）
- **挂机补回复**：重连后翻最近会话，把 2 分钟到 24 小时内漏回的私聊错峰补一句，已补的跨重启去重
- **新好友**：自动通过申请（每日上限），通过后延迟 30–90 秒发一次自我介绍，每人只发一次
- **安全兜底**：明确的自伤 / 被伤害表达走固定话术，直接给 12356 和 110/120，不经过模型，也不写入长期记忆
- **QQ 空间**：读好友动态和自己发的说说；发说说只做草稿，必须在私聊里二次确认，且只认 `QQ_OWNER_ID`
- **中控台**：三端状态、行为流、LLM 用量与成本、启停与接管，全部本机

## 架构

```
QQ 客户端 ── NapCat ── 反向 WS :3001 ── qq_agent.py
                                            │
                       ┌────────────────────┼────────────────────┐
                       │                    │                    │
                  core/memory.py       core/llm.py         表情库 / 图片
                  SQLite 记忆           DeepSeek API        vendor/…（本地）
                       │                    │
                       └──────────┬─────────┘
                                  │
                         metrics.db（调用与事件）
                                  │
                          panel/server.py :3002
```

`qq_agent.py` 是唯一入口：WebSocket 收事件、去抖、拼上下文、调模型、自检、发送。`core/memory.py` 管历史与长期记忆，`core/llm.py` 统一走 DeepSeek 并记录 token 用量。

## 快速开始

1. **准备小号**，用手机登录。
2. **装 NapCat**，用 NapCat Shell 登录这个 QQ 号，在 WebUI 里配置 OneBot 11 反向 WebSocket：`ws://127.0.0.1:3001/`，token 与 `QQ_WS_TOKEN` 一致。WebUI 和 HTTP 都只听 `127.0.0.1`。
3. **配置**：`cp .env.example .env`，至少填 `DEEPSEEK_API_KEY`、`QQ_WS_TOKEN`、`QQ_OWNER_ID`。
4. **装依赖**：`pip install -r requirements.txt`
5. **启动**：`python qq_agent.py`；要中控台就再 `python panel/server.py`，浏览器打开 `http://127.0.0.1:3002/`。
6. Windows 上想常驻，双击 `一键上线.bat`，或用 `startup/register_autostart.ps1` 注册登录自启。

主要开关都在 `.env.example` 里，常用几个：

| 变量 | 作用 |
| --- | --- |
| `QQ_CATCHUP` | 挂机补回复总开关 |
| `QQ_AUTO_APPROVE` / `QQ_APPROVE_MAX` | 自动通过好友申请及每日上限 |
| `QQ_QUIET_END` | 道过晚安后对方只回「嗯」就不再多说一句 |
| `QQ_DEBOUNCE` / `QQ_DEBOUNCE_MAX` | 连发合并的等待时间 |
| `QQ_TYPING` | 是否显示「正在输入」 |
| `QQ_MOOD` | 是否按情绪状态调语气 |
| `QQ_RHYTHM` / `QQ_REVIEW` | 节奏与发送前自检 |

## 几个设计决定

**人设短，约束结构化。** 人设写到 60 条规则时会互相冲突，模型反而写出作文腔。现在的做法是人设压到 25 条左右，把「发几条、多少字、要不要问」交给代码里的形态骰子，模型只负责用她自己的话说。

**样例只给形态，不给台词。** 模型会逐字复读人设里的例句，所以人设里不放可引用的句子，只用描述性语句说明「这条按哪种方式来」。

**语域跟着真实语料走。** 参考 LCCC（微博真实多轮对话）和公开的微信一对一聊天：中位句长 9–18 字、约六到八成不带标点、多数回复和上一句没有字面重合。所以回复短、可以跳话题、不必接住每句话。

**纯代码能拦的不调模型。** 标点清理、拆条、问句数量、重复开头、括号动作冷却、超长拆分都在发送前用正则做，不额外花钱。

**记忆是背景，不是指令。** 注入时只取与当前话题相关的少量条目，对方纠正以对方为准；敏感信息不入库；用户随时可查可删。

## 安全与合规

- QQ 侧走 NapCat 的非官方协议，**只能用小号**，主号有被风控或踢下线的风险。
- 只回复进来消息，或用户明确授权的对象；不会主动给陌生人发消息。
- 发说说、改资料这类对外可见的动作必须人工确认。
- agent、中控台、NapCat WebUI/HTTP 全部只绑 `127.0.0.1`。
- `.env`、`*.db`、浏览器 profile、二维码、日志都不进仓库（见 `.gitignore`）。
- 记忆只存本地，可按人查看和删除。

## 已知限制

- 协议依赖 NapCat，QQ 掉登录只能手机扫码恢复；自愈脚本能拉起进程，替不了扫码。
- 只做了私聊；群聊、图片/视频说说上传、抖音/B站模块都没有放进这个仓库。
- 记忆整理是后台异步的，刚说完的事可能要过几轮才进长期记忆。
- 语气只在真实聊天里验收过一部分场景，仍会偶尔写得像模板。
